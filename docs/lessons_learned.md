# 学んだこと

書くのは「起きたこと」ではなく「次はどうするか」。
同じ教訓が2回出たら、箇条書きを増やさず `.claude/rules/` の該当ファイルへ昇格させる。

## 2026-10-21

- **掲載文の書き方を user から指摘された（「AIっぽい・長い・まわりくどい」）。**
  次からは、文章を書いたら出す前に決め台詞・長い連結文・括弧の補足・重複が無いか読み直す。
  書き方の決まりは `.claude/rules/content.md` が正（文章の規約として先に置いた）
- **`Reveal` の中身は、スクロールするまで透明。** 全体スクショを撮ったら作品が1件しか
  写らず、壊れていると思いかけた。次からは、撮る前にページの一番下までスクロールする
- **Chakra v3 の semantic token は、ライト / ダークの差を `value: { _light, _dark }` に書く。**
  キーに `_dark: { fg: ... }` と置くと、条件ではなく `brand-_dark-fg` という名前のトークンになり、
  エラーも出ずにダークでもライトの色のままになる（2026-08 から気づかれていなかった）。
  次からは、色のトークンを足したらブラウザで `.dark` の CSS 変数の値を読んで確かめる。
  再発は `src/components/ui/theme.test.ts` が捕まえる
- **検査スクリプトは、手元で通っても CI で落ちることがある。** `scripts/check-docs.mjs` が
  「ディスクにあるか」で判定していたため、手元にだけあるビルド成果物を指す記述が通り、
  ビルド前の CI では落ちた。次からは、実在の判定は git で追跡しているファイルに揃え、
  環境で変わるもの（ビルド成果物・インストール物）は扱いを分けて書く。
  検査を作ったら、push して CI で1回通るのを見るまでを「作った」とする
